ARCHITECTURAL INVARIANTS

The FinTech Challenge: Throughput vs Contention

Why traditional relational transaction logging fails under high transaction velocities and how our invariants resolve it.

TRADITIONAL RDBMS PERSISTENCE BOTTLENECK

Relational Insertion Deadlocks

  • Direct INSERT statements per transaction exhaust database connection pools.
  • Row-level locking and B-Tree index rebalancing throttle throughput to < 200 TPS.
  • Dual-write anomalies between operational databases and analytics warehouses.
  • Inference queries compete with transactional write threads for CPU & I/O.
FAILURE: Connection pool saturation & lock timeouts
SIC8 LAKEHOUSE INVARIANT PRODUCTION RULE

Zero-DB-Inserts Streaming

  • Zero relational database writes during live transaction flow: direct to Amazon MSK.
  • PostgreSQL used strictly for demographic state, replicated asynchronously via WAL CDC.
  • Low-latency feature hydration from in-memory Redis cluster (< 2ms retrieval).
  • Partitioned S3 micro-batches (json.gz) decoupled from downstream Delta Lake ingestion.
INVARIANT: Total separation of live streams from OLTP storage
99.99% INGESTION UPTIME ZERO DB LOCKS

DECISION LOG

Architecture Trade-Offs & Technology Selections

Deliberate engineering decisions made between conflicting technical paths to maximize performance and maintainability.

Kafka vs RabbitMQ

Selected Kafka for partitioned persistent log storage and replayability over RabbitMQ AMQP routing.

→ Replay up to 7 days

Zero-DB-Inserts vs Direct Database Logging

Bypassing RDBMS inserts prevents connection pool exhaustion and deadlocks under burst traffic. PostgreSQL is reserved for demographic master data via Debezium CDC.

→ Eliminates 100% of OLTP lock contention

LightGBM vs Deep Learning (MLP/LSTM)

LightGBM evaluates in 1.4ms on standard CPU workers with 99.4% ROC-AUC, avoiding heavy GPU cluster overhead, cold-start model latency, and non-deterministic deep learning delays.

→ CPU efficiency with sub-10ms SLA

Databricks Lakehouse

Delta Lake unified storage eliminates ETL sync between batch lakes and relational analytical marts.

→ Single source of truth
VERDICT: Engineered for extreme horizontal scalability, sub-10ms SLAs, and low total cost of cloud ownership.
